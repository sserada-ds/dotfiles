# 出力テンプレート

`onboard` のまとめはこの構成で書く。該当しない節は省略してよい（空の見出しは残さない）。

## テンプレート

```markdown
# <プロジェクト名> キャッチアップ

## 1. 概要

<目的を 1〜2 文。誰が何のために使うか。>

- 規模: <言語、ファイル数、コミット数、最終更新>
- 状態: <活発か停滞か、主な貢献者、未コミットの変更>

## 2. 技術スタック

| 領域 | 採用 | 根拠              |
| ---- | ---- | ----------------- |
| 言語 | ...  | `package.json:12` |

## 3. 構成

<主要ディレクトリの役割。ファイル数の多い順ではなく、理解に必要な順で。>

## 4. 代表的な流れ: <例: リクエスト / コマンド / ジョブ>

1. 入口: `src/server.ts:30` ...
2. ...

## 5. 外部とのつながり

<データストア、外部 API、環境変数名（値は書かない）、CI。>

## 6. 規約

<lint / format、テストの書き方、コミットの流儀。>

## 7. 動かし方

| 目的   | コマンド    | 裏取り        |
| ------ | ----------- | ------------- |
| テスト | `make test` | `Makefile:14` |

## 8. 注意点・リスク

<よく変わるファイル、古い記述、機密ファイル、壊れやすい箇所。>

## 9. 未確認・要確認

<確認できていないこと、推測したこと。>

## 10. 読む順番

1. `README.md`
2. ...（5 ファイル以内）

Last reviewed commit: <sha>
```

## 書き方の例

悪い例（根拠がなく、推測が事実の顔をしている）:

> 認証は JWT を使っていて、ミドルウェアで検証している。

良い例（根拠と確度が分かる）:

> 認証は JWT ベース。検証は `src/middleware/auth.ts:18` の `verifyToken`。鍵の取得元は環境変数 `JWT_SECRET`（`.env.example:4`）。リフレッシュトークンの扱いは**未確認**。
