# ADR テンプレート（Architecture Decision Record）

覆しにくい判断（技術選定、データモデル、公開インターフェース、セキュリティ方針）を、後から理由を辿れるように残す。書くのは**決定した（または決定しようとしている）ことだけ**で、未決の検討は設計書か RFC に書く。承認前は状態を「提案」とし、承認が出たら「承認」にして保存する。

## 使いどころ

- 数か月後に「なぜこうなっているのか」と聞かれそうな判断。
- 代替案が現実的にあり、選ばなかった理由が残る価値のある判断。
- 日常的な実装の選択は ADR にしない。

## テンプレート

```markdown
# ADR-<連番>: <決定を一文で>

- 状態: 提案 / 承認 / 却下 / 置き換え済み（ADR-<番号> により）
- 日付: YYYY-MM-DD

## 背景

<判断が必要になった状況と、制約。>

## 決定

<何を採用するか。能動態で、一文から数文。>

## 検討した代替案

- <案 B>: 採らなかった理由
- <案 C>: 採らなかった理由

## 結果

- 良い点: ...
- 悪い点・受け入れるトレードオフ: ...
- 今後必要になること: ...
```

## 運用

- 保存先は既存の `docs/adr/`、`docs/decisions/` などの慣習に合わせる。なければ `docs/adr/` を提案する。
- 連番は既存の最大番号の次にする。ファイル名は `0007-use-postgres.md` のように番号と短い題にする。
- 承認済みの ADR は書き換えない。判断を変えるときは、新しい ADR を書き、古い方の状態を「置き換え済み」にする。
